## 1. Модуль QGIS Isoliner3D

Хранилище `github.com/Valery35/qgis-isoliner3d`.

- `main` - выпуск 1.4.13 (тег `1.4.13`) и после него исправление
  разбора XML чужого проекта (`scenes.py`, сущности XML). Выпуска
  с исправлением нет, оно войдёт в следующий.
- `wip/1.5.0-arch` - новая архитектура, на GitHub. Её же установил
  в профиль QGIS для проверки.

Что сделано в новой архитектуре:

- `toolspec.py` - инструмент как объект: описание (`Tool`, `Param`)
  и расчёт `run(values, report)` на простых данных без QGIS.
- `tools/` - инструменты-объекты: 2.23 `fill_volume.py`, 2.24
  `sweep_body.py`, реестр `TOOLS`.
- `algorithms.py` - обёртка `SpecAlgorithm`, классы 2.23 и 2.24 тонкие.
  Имя и название остаются в классе строками: по ним ищут панель,
  проверки AST и сборщики руководства.
- `scene_package.py` - пакет сцены `.i3dscene`. Окно просмотра пишет
  его через «Выгрузить сцену», формат «Пакет сцены Isoliner3D».
- `tools/export_tools.py` - `tools.json`, строки на двух языках,
  с шаблонами сообщений расчёта.
- `tools/make_fixtures.py <папка>` - проверочные данные для Rust.
  После правки формата или расчёта в модуле: собрать в
  `C:\Dev\isoliner-scene\fixtures` и прогнать `cargo test --workspace`.
- `ARCHITECTURE.md` - уровни модуля и порядок переноса остальных
  инструментов.

Проверено в QGIS 4.0.3 на машине автора: 2.24 - штрек 4x3x180 м даёт
2160 м3, 2.23 - 25 % тела дают уровень -299,25 м при почве -300 м.

Не проверено в окне QGIS (только тестами без QGIS): кнопка видео,
меню видов, шкалы на разрезе (это 1.4.13), выгрузка пакета сцены.

### Как работать с модулем

- Тесты: `python -m pytest isoliner3d/tests` в корне хранилища. Нужны
  NumPy и pytest. Static-тесты разбирают `algorithms.py` через AST,
  QGIS для них не нужен.
- Проверки перед коммитом: `python tools/state_snapshot.py` (снимок
  в `AGENTS.md` модуля), `python tools/check_prose.py`.
- Установка в QGIS для проверки: содержимое папки `isoliner3d` ветки
  копируется в `%APPDATA%\QGIS\QGIS4\profiles\default\python\plugins\isoliner3d`
  (кроме `libs` и `doc`), затем перезагрузка модуля.
- Если подключён MCP-сервер QGIS: долгий расчёт запускается через
  `QTimer.singleShot`, итог пишется в файл, файл читается потом.
  Пока QGIS считает, никаких вызовов MCP: QGIS падал от этого.
- Git автор ведёт через GitHub Desktop, `git.exe` -
  `%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd`.

### Правила модуля, которые легко забыть

- Лицензия модуля не меняется: «Лицензию не меняй. Это мои модули.»
- Публикация (GitHub-выпуск, каталог plugins.qgis.org, Telegram,
  Reddit, форумы) - только по слову автора. На форумах разработчиков
  (OSM, Rust) - только словами автора.
- Сканер каталога: исправляются только ошибки, на которых каталог
  отклоняет загрузку (сейчас это `except: pass` и `except: continue`
  без `# nosec`). Предупреждения были всегда, их не трогаем.
- Галочки согласия в форме каталога ставит автор.
- Файлы не удаляются насовсем. Архивы автора в Dropbox и профили
  модулей не трогаются, кроме установки на проверку.
- Тексты по-русски: тире ` - `, без точки с запятой, без слов
  «софт», «честный», «прямо».

## 3. Isoliner3D для RustGIS

Приложение `apps/isoliner-rustgis` этого хранилища, решение автора
от 12 ноября 2026 года. Расширение-процесс RustGIS по образцу
RustPlanetX: `isoliner-rustgis rustgis-plugin`, манифест
`apps/isoliner-rustgis/plugin.json`. В `planetx-lite` ничего
не подключается: RustPlanetX - глобус PlanetX, одна функция - один дом.
Образец протокола - `planetx-lite`, `crates/ui/src/rustgislink.rs`
и `crates/desktop/src/lib.rs`, манифест - `C:\Dev\rustplanetx\plugin.json`.

Решение автора от 13 ноября 2026 года - «Один модуль»: Isoliner3D
для RustGIS - одно расширение `apps/isoliner-rustgis`, в нём сцена,
инструменты и документация.

- Сцена подключается кодом Isoliner Scene как библиотекой, без копии:
  та же плашка (`toolbar.json`), окно «Параметры сцены»
  (`scene_params.json`), «О программе» (`about.json`). Слои проекта
  RustGIS идут в сцену.
- Инструменты - по общему `tools.json` модуля: окно инструмента
  с полями, запуск, итог слоем в проект RustGIS. Сначала те, что уже
  считаются на Rust (этап 5 `doc/PLAN.md`).
- Документация - одно руководство на линейку: страницы инструментов
  собираются из `tools.json` общим с модулем генератором, глава
  о сцене общая с Isoliner Scene, своя короткая глава «Установка
  в RustGIS».
- Isoliner Scene остаётся отдельной программой: своё окно, свой
  выпуск, кнопка модуля «Открыть в Isoliner Scene».

С 13 ноября 2026 года всё, что не зависит от продукта, - в крейте
`rustgis-kit` (`C:\Dev\rustgis-kit`, своё хранилище
https://github.com/Valery35/rustgis-kit, Apache 2.0). Протокол RustGIS, раздел `tools` манифеста
и разбор полей по `tools.json`, системы координат, итог слоем,
хранилище высот, окно своим процессом, ретранслятор MCP, упаковка
`.rgplugin`. Расширение подключает его зависимостью git с тегом
(`v0.1.0`), своё у продукта - `src/product.rs`. Новая версия крейта -
новый тег в его хранилище и новый тег здесь. Тот же крейт берут
Isoliner, Topoliner и Routeliner, как - `README.md` крейта.

Расширение ведёт своя сессия Claude Code - подсессия «RustGIS»,
с 13 ноября 2026 года. Окно сцены и связь со сценой (крейт
`scene-app`, сессия RustGIS, слои проекта в сцене) - работа сессии
Isoliner Scene. Инструменты, раздел `tools` в `plugin.json`,
руководство и упаковка - работа подсессии «RustGIS».

Заготовка (шаг 1 этапа 4 `doc/PLAN.md`) сделана 12 ноября 2026 года:
команды `scene`, `tools`, `run`, проверено без RustGIS. 13 ноября
добавлена команда `about`. Ход этапа - `doc/PLAN.md`, этап 4.

В сам RustGIS ничего не ставится без слова автора, проверка в RustGIS -
по образцу RustPlanetX.

Что известно о RustGIS по проверке 13 ноября 2026 года:

- Системы координат в RustGIS есть (поправка автора «Есть ведь
  системы.»). Слой помнит систему, в которой прочитан, есть
  `layer.defineProjection`, проекции карты, пересчёт при выгрузке
  (`share.exportLayer` с `crs` для GPKG, SHP, FGB), CSV с X и Y
  в любой системе. Проверено на 0.6.0 от 9 ноября, она последняя.
- Протокол расширений системы не называет. `host.layers` кода системы
  не даёт, `host.features` и слои в запросе инструмента приходят только
  в градусах WGS 84 (так и на main, `docs/plugins.md`). Z при чтении
  слоя отбрасывается с предупреждением.
- Итог с членом GeoJSON `crs` (`EPSG:...`) RustGIS принимает и
  пересчитывает сам - и выходом инструмента, и `host.addLayer`.
- Команда (не инструмент) может выгрузить слой в любой системе:
  `share.exportLayer` с `crs` пишет Shapefile, пересчитывает сам
  RustGIS. Инструментам запросы к RustGIS запрещены, у них вход только
  в градусах.
- `host.view` отдаёт проекцию карты строкой: `mercator`, `globe`
  или `EPSG:n`.

Система сцены - как у карты (решение автора от 13 ноября 2026 года,
«для сцены надо дать возможность СК устанавливать, как для карты»):

- по умолчанию - проекция карты RustGIS, если это код EPSG в метрах;
- карта `mercator`, `globe` или в градусах - зона UTM по середине слоёв;
- код из поля `scene_crs` окна «Параметры сцены» (вкладка «Вид»,
  пометка pro, список модуля) важнее карты. Окно сцены из слоёв
  запускается с `--crs-file <temp>/isoliner3d/RustGIS.crs`, пишет
  выбор туда, выбор применяется при следующем нажатии «Сцена»;
- слои выгружаются в систему сцены силами RustGIS, код пишется в пакет
  (`crs.authid` и `state.scene_crs`, как у модуля);
- итог тел Isoliner3D в слоях держит сцену в зоне UTM: тела с высотой
  лежат в градусах, перевести их в другую систему расширению нечем;
- отдельная Isoliner Scene систему только показывает.

Проверено `rustgis-cli` 13 ноября: карта EPSG:32637 - пакет 32637,
выбор EPSG:32638 - пакет 32638, карта mercator - зона UTM 37.

Коды систем знает RustGIS (вкладка «Вид» → «Проекция», код EPSG или
ESRI, слои проецируются на лету), на него и опираемся. Своей таблицы
EPSG в расширении нет (решение основной сессии от 13 ноября 2026 года).

Высоты итогов (13 ноября 2026 года, задание автора «Давай первые два
подсессии»). Слой RustGIS Z не держит, поэтому итоги с высотой (тела,
стволы, интервалы, точки) расширение хранит рядом со сценой
(`<temp>/isoliner3d/RustGIS.bodies/<слой>.json`: первые точки плана
и геометрии с Z в градусах). Слой узнаётся по имени и первым точкам
объектов. Инструмент, получивший такой слой, берёт тела и линии с Z,
сцена из слоёв - тоже. Объёмный итог каждого инструмента пишется
пакетом `<temp>/isoliner3d/RustGIS.results/<инструмент>.i3dscene`
и открывается своим окном сцены. Рядом с градусами итог хранит свои
метры и зону: следующий инструмент в той же зоне берёт их без перевода
туда и обратно (ряды UTM точны до миллиметра).

В RustGIS десять инструментов: 1.09, 2.24, 2.26, 2.23, 2.11, 2.12, 2.14,
2.17, 2.18, 2.25. Расчёт 2.26, 1.09 и 2.25 перенесла в `crates/tools`
подсессия «RustGIS» с согласия сессии сцены (свои файлы на инструмент,
сверка с прогонами модуля до 1e-9). 2.13 ждёт решения автора о переносе
и растра у RustGIS. Найдено при переносе 2.26: замкнутость кольца
в `crown.py` проверялась `np.allclose` с относительным допуском - на
метрах проекта пропадала сторона кольца, модуль исправил.

Ожидание от RustGIS. Вход инструментов пока считается через зону UTM:
инструменту RustGIS не даёт ни кода системы входа, ни запросов к себе.
Автор - «Думаю, еще доработают здесь». Когда у запроса инструмента
появится код системы слоёв (или `host.*` для инструментов), вход
и итог переходят на систему проекта, UTM остаётся для карт в градусах.
То же с сессиями расширений: с ними сцена будет следить за слоями без
нажатия кнопки.
- Установленная у автора сборка (от 6 ноября) сессий расширений
  не знает. Каждая команда - отдельный запуск программы. Запросы
  `host.layers` и `host.features` работают внутри запуска, ответ
  RustGIS приходит строкой без `id`. Поэтому сцена из слоёв строится
  одним запуском, а при открытом окне команда «Сцена» только
  переписывает пакет, окно перечитывает его само. Следить за слоями
  без нажатия сможет RustGIS с сессиями.
- Окно инструмента рисует сам RustGIS (панель Tools) по разделу
  `tools` в `plugin.json`, раздел собирается из `tools.json`.
- `rustgis-cli run --plugin dist/isoliner3d` проверяет расширение
  без установки.

Решение подсессии «RustGIS» по 2.17 (13 ноября 2026 года, после
поправки автора):

- Устья точечным слоем - как у остальных инструментов. Градусы
  переводятся в метры зоны UTM, итог - обратно в градусы. Сюда же
  CSV с X и Y, добавленный с кодом системы: RustGIS сам ставит точки.
- Устья таблицей без точек - поля X и Y в метрах таблицы, как у модуля.
  Код системы X и Y - поле окна «Система координат X и Y (EPSG)».
  Расчёт идёт в метрах таблицы, итог уходит в RustGIS в тех же метрах
  с кодом системы, RustGIS ставит стволы на место сам. Без кода -
  ошибка, а не стволы неизвестно где.
- Отметка устья - из поля, Z у слоя RustGIS не бывает.

Пересчёт градусов в произвольную систему по коду EPSG внутри
расширения не делается: таблица кодов `crs-definitions` идёт
под CC0-1.0, её нет в `deny.toml`. Нужен он станет, если инструментам
понадобится вход в метрах системы проекта - решает автор.
