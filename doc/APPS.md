## 1. Модуль QGIS Isoliner3D

Хранилище `github.com/Valery35/qgis-isoliner3d`.

- `main` - выпуск 1.4.13 (тег `1.4.13`) и после него исправление
  разбора XML чужого проекта (`scenes.py`, сущности XML). Выпуска
  с исправлением нет, оно войдёт в следующий.
- `wip/1.5.0-arch` - новая архитектура, на GitHub. Её же установил
  в профиль QGIS для проверки.

Что сделано в новой архитектуре:

- `toolspec.py` - инструмент как объект: описание (`Tool`, `Param`)
  и расчёт `run(values, report)` на простых данных без QGIS.
- `tools/` - инструменты-объекты: 2.23 `fill_volume.py`, 2.24
  `sweep_body.py`, реестр `TOOLS`.
- `algorithms.py` - обёртка `SpecAlgorithm`, классы 2.23 и 2.24 тонкие.
  Имя и название остаются в классе строками: по ним ищут панель,
  проверки AST и сборщики руководства.
- `scene_package.py` - пакет сцены `.i3dscene`. Окно просмотра пишет
  его через «Выгрузить сцену», формат «Пакет сцены Isoliner3D».
- `tools/export_tools.py` - `tools.json`, строки на двух языках,
  с шаблонами сообщений расчёта.
- `tools/make_fixtures.py <папка>` - проверочные данные для Rust.
  После правки формата или расчёта в модуле: собрать в
  `C:\Dev\isoliner-scene\fixtures` и прогнать `cargo test --workspace`.
- `ARCHITECTURE.md` - уровни модуля и порядок переноса остальных
  инструментов.

Проверено в QGIS 4.0.3 на машине автора: 2.24 - штрек 4x3x180 м даёт
2160 м3, 2.23 - 25 % тела дают уровень -299,25 м при почве -300 м.

Не проверено в окне QGIS (только тестами без QGIS): кнопка видео,
меню видов, шкалы на разрезе (это 1.4.13), выгрузка пакета сцены.

### Как работать с модулем

- Тесты: `python -m pytest isoliner3d/tests` в корне хранилища. Нужны
  NumPy и pytest. Static-тесты разбирают `algorithms.py` через AST,
  QGIS для них не нужен.
- Проверки перед коммитом: `python tools/state_snapshot.py` (снимок
  в `AGENTS.md` модуля), `python tools/check_prose.py`.
- Установка в QGIS для проверки: содержимое папки `isoliner3d` ветки
  копируется в `%APPDATA%\QGIS\QGIS4\profiles\default\python\plugins\isoliner3d`
  (кроме `libs` и `doc`), затем перезагрузка модуля.
- Если подключён MCP-сервер QGIS: долгий расчёт запускается через
  `QTimer.singleShot`, итог пишется в файл, файл читается потом.
  Пока QGIS считает, никаких вызовов MCP: QGIS падал от этого.
- Git автор ведёт через GitHub Desktop, `git.exe` -
  `%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd`.

### Что дальше в модуле

1. Перенос остальных 30 инструментов в объекты, по одному, порядок
   в `ARCHITECTURE.md`. Первыми - тела и линии: 2.11-2.15, 2.17, 2.18.
   На каждый: `run` в `tools/`, тонкий класс, тест на простых данных,
   прогон в `tool_runs.json` через `make_fixtures.py`.
2. Окно просмотра: кнопка «Открыть пакет сцены» - сцена из пакета
   без слоёв проекта.
3. Точки (пробы, борозды) в пакет сцены: окно модуля их сейчас
   не выгружает (`_export` в `viewer_dialog.py`). Найдено при приёмке
   этапа 1 Isoliner Scene. После правки - образец в `fixtures/`
   и чтение точек в Isoliner Scene.
4. Проверка в окне QGIS того, что перечислено выше как не проверенное.

### Правила модуля, которые легко забыть

- Лицензия модуля не меняется: «Лицензию не меняй. Это мои модули.»
- Публикация (GitHub-выпуск, каталог plugins.qgis.org, Telegram,
  Reddit, форумы) - только по слову автора. На форумах разработчиков
  (OSM, Rust) - только словами автора.
- Сканер каталога: исправляются только ошибки, на которых каталог
  отклоняет загрузку (сейчас это `except: pass` и `except: continue`
  без `# nosec`). Предупреждения были всегда, их не трогаем.
- Галочки согласия в форме каталога ставит автор.
- Файлы не удаляются насовсем. Архивы автора в Dropbox и профили
  модулей не трогаются, кроме установки на проверку.
- Тексты по-русски: тире ` - `, без точки с запятой, без слов
  «софт», «честный», «прямо».

## 3. Isoliner3D для RustGIS

Приложение `apps/isoliner-rustgis` этого хранилища, решение автора
от 12 ноября 2026 года. Расширение-процесс RustGIS по образцу
RustPlanetX: `isoliner-rustgis rustgis-plugin`, манифест
`apps/isoliner-rustgis/plugin.json`. В `planetx-lite` ничего
не подключается: RustPlanetX - глобус PlanetX, одна функция - один дом.
Образец протокола - `planetx-lite`, `crates/ui/src/rustgislink.rs`
и `crates/desktop/src/lib.rs`, манифест - `C:\Dev\rustplanetx\plugin.json`.

Решение автора от 13 ноября 2026 года - «Один модуль»: Isoliner3D
для RustGIS - одно расширение `apps/isoliner-rustgis`, в нём сцена,
инструменты и документация.

- Сцена подключается кодом Isoliner Scene как библиотекой, без копии:
  та же плашка (`toolbar.json`), окно «Параметры сцены»
  (`scene_params.json`), «О программе» (`about.json`). Слои проекта
  RustGIS идут в сцену.
- Инструменты - по общему `tools.json` модуля: окно инструмента
  с полями, запуск, итог слоем в проект RustGIS. Сначала те, что уже
  считаются на Rust (этап 5 `doc/PLAN.md`).
- Документация - одно руководство на линейку: страницы инструментов
  собираются из `tools.json` общим с модулем генератором, глава
  о сцене общая с Isoliner Scene, своя короткая глава «Установка
  в RustGIS».
- Isoliner Scene остаётся отдельной программой: своё окно, свой
  выпуск, кнопка модуля «Открыть в Isoliner Scene».

Заготовка (шаг 1 этапа 4 `doc/PLAN.md`) сделана 12 ноября 2026 года:
команды `scene`, `tools`, `run`, проверено без RustGIS. 13 ноября
добавлена команда `about`. Ход этапа - `doc/PLAN.md`, этап 4.

В сам RustGIS ничего не ставится без слова автора, проверка в RustGIS -
по образцу RustPlanetX.
