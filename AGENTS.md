## Что это

Isoliner Scene - сцена модуля Isoliner3D без QGIS. Программа на Rust
для Windows, Linux и macOS. Открывает пакет сцены `.i3dscene`, который
пишет окно просмотра Isoliner3D, и показывает его той же камерой: тела,
линии, прозрачность, преувеличение, виды облёта.

Второе назначение - Isoliner3D для RustGIS, приложение
`apps/isoliner-rustgis` этого хранилища, решение автора от 12 ноября
2026 года. Это расширение-процесс RustGIS: сцена `.i3dscene` в окне
Isoliner Scene, инструменты по tools.json (2.11, 2.12, 2.14, 2.17, 2.18,
2.23, 2.24). В RustPlanetX
(`planetx-rustgis` из `C:\Dev\planetx-lite`) Isoliner3D не встраивается:
там глобус PlanetX, одна функция - один дом.

Заведён 12 ноября 2026 года по решению автора. Устройство уровней -
`ARCHITECTURE.md` модуля Isoliner3D.

## Связь с модулем Isoliner3D

- Модуль - `C:\Dev\qgis-isoliner3d`, хранилище
  `github.com/Valery35/qgis-isoliner3d`, Python, GPL-2.0-or-later.
  Ветка новой архитектуры - `wip/1.5.0-arch`.
- Связь - только файлы:
  - `.i3dscene` - пакет сцены, модуль пишет (`scene_package.py`),
    программа читает и пишет обратно;
  - `tools.json` - описания инструментов-объектов
    (`tools/export_tools.py` модуля).
- Проверочные данные - папка `fixtures/`. Их собирает модуль:
  `python tools/make_fixtures.py <папка>` в рабочей копии модуля.
  Файлы здесь не правятся руками. Изменился формат или расчёт в модуле -
  пересобираются образцы, потом правится код здесь, тесты сверяются
  с образцами.
- Код модуля - источник переноса. Перенос идёт с тестами: сначала
  образцы из модуля, потом код, потом сверка. Перенесённая функция
  называется в комментарии файлом модуля (`перенос flight.py`).

## Раскладка

| Крейт | Что | Зависит от |
|---|---|---|
| `crates/scene-format` | пакет `.i3dscene`: scene.json, GLB, чтение и запись | serde, zip |
| `crates/scene-core` | камера окна Isoliner3D, облёт, охват и объём тел | scene-format, glam |
| `crates/render` | отрисовка на wgpu в текстуру, снимок кадра | scene-core, wgpu |
| `crates/tool-spec` | описания инструментов из tools.json, значения, отчёт, результат | serde |
| `crates/tools` | расчёты инструментов: 2.11, 2.12, 2.14, 2.17, 2.18, 2.23, 2.24 | tool-spec |
| `apps/isoliner-scene` | окно: eframe и egui, та же программа страницей в браузере (Trunk, `web.rs`) | все выше |
| `apps/isoliner-rustgis` | расширение RustGIS: `rustgis-plugin`, `plugin.json`, команды `scene`, `tools`, `run` | scene-format, tool-spec, tools |

Нижний слой не зависит от верхнего. `tool-spec` и `tools` не знают
сцены, `scene-format` не знает камеры.

## Решения, взятые из модуля

- Камера - поза окна Isoliner3D (pyqtgraph): точка взгляда, удаление,
  азимут, наклон, раствор. Перспектива - раствор по горизонтали,
  параллельная проекция - по вертикали. Формулы в `scene-core/camera.rs`,
  повторяют `GLViewWidget`.
- В пакете камера в настоящих координатах. В окне сцена сдвинута
  на центр, высоты умножены на преувеличение (`Frame`). Камера хранится
  в настоящих координатах и переводится на каждом кадре.
- Вершины в GLB - сдвиг от круглой точки начала в float32, настоящая
  координата - в double. В видеокарту мировые координаты не попадают.
- Облёт: smoothstep, азимут короткой дугой, удаление в логарифме,
  округление числа кадров к чётному, как `round` в Python.

## Правила кода

- Как в PlanetX Lite: нет `unsafe`, `unwrap`, `expect`, `panic!`,
  `todo!` в рабочем коде. Входной файл считается враждебным: размеры,
  смещения и номера вершин проверяются до чтения.
- В тестах `unwrap` разрешён атрибутом в начале файла теста.
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`
  и `cargo test --workspace` перед каждым коммитом. То же делает CI.
- Версии общих зависимостей - как в `C:\Dev\planetx-lite\Cargo.toml`
  (wgpu, eframe, glam, zip). Крейты сцены подключаются туда, расхождение
  версий там недопустимо.
- Лицензия - Apache 2.0, как у PlanetX Lite и RustGIS. Зависимости только
  под разрешительными лицензиями, список - `deny.toml`. Новая лицензия
  в список - только с согласия автора.
- Комментарии и документация в коде - по-русски, шапка с лицензией
  в каждом файле:

  ```
  // Isoliner Scene - сцена Isoliner3D без QGIS.
  // Copyright (C) 2026 ООО «Информ++». Лицензия Apache 2.0.
  // SPDX-License-Identifier: Apache-2.0
  ```
- Тексты окна - через `i18n.rs`, русский и английский. Тексты
  инструментов - из `tools.json`, переводы там.
- Сравнения с порогом - в относительных величинах или в пикселях.

## Проверки

- `scene-format`: пакет демо модуля читается, охват и цвета частей
  совпадают с `scene_demo.expected.json`, запись и чтение обратно
  ничего не теряют, порченый файл даёт ошибку, а не падение.
- `scene-core`: облёт кадр в кадр как `flight.py`, объёмы тел как
  в модуле.
- `tools`: 2.24 - вершины, грани, длина, площадь, объём и сообщения
  отчёта слово в слово как в модуле. 2.23 - уровень и объёмы в допуске
  из `tool_runs.json`, заполненная часть замкнута.
- `render`: кадр демо без окна. Нужна видеокарта или программная
  отрисовка (lavapipe, пакет `mesa-vulkan-drivers`). Без них тест
  пропускается с записью в журнал. Кадр - `target/snapshots/scene_demo.ppm`.
- `isoliner-rustgis`: команды `plugin.json` совпадают с кодом, у каждой
  строки есть перевод. Все прогоны `tool_runs.json`, поданные запросом
  JSON, дают те же объекты, значения и сообщения, что модуль. Пакет
  сцены читается до запуска окна, ошибка уходит в RustGIS. Порченый
  ввод даёт ошибку, а не падение.

## Приёмка работы

Задача имеет признак готовности, который можно проверить. Признак
называется до начала работы. «Готово» говорится только после прогона,
без прогона - «сделано, не проверялось». Разобранная ошибка получает
тест, который краснеет на прежнем поведении.

## Что решает автор

- номер версии и момент выпуска
- состав этапов плана и их приёмка
- лицензия и публикация
- величины умолчаний, которые видит пользователь

установка программ на машину автора. Готовность к такому действию
сообщается, само действие ждёт ответа. Git автор ведёт через GitHub
Desktop, команды `git` в PATH нет: `git.exe` берётся из папки GitHub
Desktop (`%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd`).
